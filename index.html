Terminology reference and consistency findings for Galileo localisation, 22 languages

The project's terminology reference: one canonical translation per term, per locale. "Decided" terms have been reviewed and have a documented reason for the choice. "Proposed" terms are reused often enough across the app that they need one canonical form too, but nobody has decided it yet - each shows the variant currently used most, as a starting point, next to every variant actually in use.

    1. Placeholder syntax mismatches high priority

    Same English text, two different keys, and the keys use different placeholder syntax ([%1$s:variable] vs plain {variable}) for what should be the same variable. This repeats across most locales because it traces back to one duplicated source key, not many separate translator mistakes. If the app does not render {variable} as a placeholder, every locale using that form will show the literal text to users.

    2. Same English label, different translation depending on where it appears termbase gap

    These English strings are reused at many keys project-wide, and most locales translated them differently in different places. This is not really a translation error, it is the project never settling on one canonical form. Moved to its own place: see the , "Proposed terms" section.

    3. Long tail lower priority

    Everything else: English strings inconsistent in only one or a few locales. Still searchable in the Search & browse tab, not repeated here as a list because most of these need a case-by-case look rather than a single termbase decision.

    Methodology

    Built from a full manual export of the Galileo Lokalise project (en-GB plus all 22 target locales), taken 2 September 2026. Every English source string used at more than one key was compared across all the keys that share it, per locale. A locale is flagged as inconsistent for that string when it used more than one distinct, non-empty translation across those keys. This is an exact-match, first-pass check: word-for-word identical strings only, no fuzzy matching or machine judgement of meaning.

    Flagged instances were then split into three groups: placeholder syntax mismatches (a variable token differs between variants, a functional risk), substantive wording differences (real difference in the words used), and trivial differences (identical once punctuation, case and spacing are ignored). The findings tab leads with placeholder mismatches and the group of terms inconsistent in most locales at once, since those are the highest-value fixes.

    Scope and limits

    This is exact-match only. It will not catch a string that means the same thing but is phrased differently in the English source itself, and it will not catch translations that are wrong but internally consistent. Coverage is the 22 Galileo target locales plus en-GB as the source.
